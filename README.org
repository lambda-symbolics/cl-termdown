#+title: cl-termdown

cl-termdown parses a restrained Markdown subset into terminal-oriented semantic
spans. It preserves Unicode cell widths, whole-word wrapping, bullets and
numbered lists, inline emphasis and code, bounded pipe tables, fenced syntax
highlighting, and speculative streaming previews.

Rows are lists of neutral cons spans whose =car= is a keyword role and whose
=cdr= is text. The caller styles them.

* Usage

#+BEGIN_SRC lisp
(asdf:load-system :cl-termdown)

(let ((renderer (termdown:markdown-renderer-create :width 48)))
  (termdown:markdown-render-line
   renderer
   "- render **strong** and `code` spans"))
;; => (((:PLAIN . "  ")
;;      (:BRAND . "• ")
;;      (:PLAIN . "render ")
;;      (:STRONG . "strong")
;;      (:PLAIN . " and ")
;;      (:CODE . "code")
;;      (:PLAIN . " spans")))
#+END_SRC

One renderer retains fenced-code and pipe-table state across logical lines.
Call =markdown-render-line= when a newline commits that logical line.

#+BEGIN_SRC lisp
(multiple-value-bind (committed live retained)
    (termdown:markdown-render-partial renderer "unfinished **strong")
  (values committed live retained))
#+END_SRC

* Public API

- =markdown-renderer-create=: create a stateful renderer with =:width= and
  optional pure hooks, including in previews:
  - =:heading-role-function= maps heading roles.
  - =:inline-decorator= receives unwrapped semantic items for a prose line,
    heading or table cell and returns items with the same concatenated text.
    It runs after block role mapping and before wrapping. Preserve literal
    styles and existing widget actions when restyling prose.
  - =:fence-widget-function= receives the original source and copy label
    and returns an application item.
- =markdown-renderer-width=: read its effective row width
- =markdown-renderer-closed-code-source=: original body of the most recently
  closed fence, cleared when another fence opens
- =markdown-render-line=: render and commit one logical line
- =markdown-render-inline=: render inline Markdown within an exact width
- =markdown-inline-spans=: sanitized, unwrapped inline Markdown items
- =markdown-render-partial=: preview an uncommitted logical line as three values
- =markdown-render-finish=: flush an unfinished buffered diagram as source at EOF
- =markdown-render-chunk=: consume text after optional =:pending= text, returning
  committed rows, live rows and retained pending text; =:finished-p= flushes EOF
- =markdown-render-source=: render a complete document and flush EOF; both source
  and chunk operations accept =:trailing-empty-p= to render an empty final line
- =make-span=, =span-p=, =span-role=, =span-text=: neutral =(role . text)= spans
- =spans-width=: Unicode cell width of a joined, sanitized single-line item row
- =column-widths=: allocate cell-aware table column widths
- =fit-text=: clip and align a single table cell
- =spans-text=: concatenate sanitized visible text, optionally as one line
- =fit-spans=: clip sanitized items by cells without splitting graphemes or
  losing widget actions, including graphemes split across adjacent items
- =pad-spans=: clip or pad to an exact cell width, with an optional padding =:role=
- =split-first-line=: split before the first newline, retaining widget actions
- =item-role=, =item-text=, =item-with-text=: inspect or relabel spans and widgets;
  =item-with-text= retains actions and accepts an optional replacement =:role=
- =render-spans=: sanitized presentation with an optional trusted
  =:style-function= accepting =(role text)= and returning presentation
- =make-widget=, =widget-p=, =widget-role=, =widget-label=, =widget-action=:
  a displayed label with a semantic role and an application action
- =presentation-spans=: explicit display-only projection of widgets to spans
- =widget-regions=: =(start end action)= character extents indexing =spans-text=,
  with an optional =:start= offset; use =:unit :cell= for terminal hit testing
  with whole-grapheme extents across item boundaries
- =shift-regions=, =region-action=: move regions or find the action at an offset
  in the selected unit
- =selector-table-rows=: semantic table rows for a vertical Clinedi selector,
  with =:column-functions=, =:group-function= and configurable roles;
  other selector arrangements signal =selector-arrangement-error=

Semantic roles include =:plain=, =:brand=, =:dim=, =:strong=, =:emphasis=,
=:code=, =:code-copy=, =:notice=, and Colordiff's =:syntax-*= roles.

* Development

#+BEGIN_SRC sh
./script/bootstrap
./script/check
./script/check --fix
#+END_SRC

=./script/check= runs =CL-TERMDOWN/TESTS= in an isolated source registry, then
checks the source with [[https://github.com/lambda-symbolics/cheque][cheque]] as
=cheque.sexp= configures it. =--fix= skips the tests and repairs what cheque can
repair. cheque and its tools are development dependencies: =checks/qlfile=
lists them, and the check installs them on first use into
=~/.cache/cheque/tools/=.

* Dependencies

cl-termdown uses Clinedi for Unicode geometry and wrapping, Clermaid for terminal
diagrams, ColorLisp and Colordiff for fenced-code highlighting, and Serapeum for
declarations. Qlot pins the tested dependency revisions.

* Mermaid fences

Fenced blocks tagged =mermaid= render through Clermaid when they close.
Read the original body from =markdown-renderer-closed-code-source= and use the
closing row's =:code-copy= span to add a copy control. Unsupported, malformed,
excessively large, or too-wide diagrams display numbered source with a =:notice=
diagnostic before it. The diagnostic includes Clermaid's failure category and
condition report, sanitized and wrapped to the renderer's terminal-cell width.
A source-limit diagnostic appears as soon as a fence exceeds the buffering limit.

Open diagrams appear only in speculative previews. Call =markdown-render-finish=
at the end of a document or interrupted stream to display incomplete source.
See Clermaid's README for the supported syntax.

Flowchart subgraphs render as labeled frames, including nested groups and edges
between grouped nodes. For example:

#+BEGIN_SRC mermaid
flowchart TD
  subgraph Local["Local machine"]
    C[Client] --> S[Server]
  end
  S --> R[Remote]
#+END_SRC

Clermaid parses the groups and draws their frames and connections. Use the same
Markdown rendering API for grouped and ungrouped diagrams.
